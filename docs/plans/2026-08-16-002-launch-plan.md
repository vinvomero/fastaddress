## Remaining steps, in order

### L1. Verification gate (in progress, automatic)
Rebuild + cargo tests + wheel + test_dropin (now incl. exception/kwarg/½/falsy checks) +
test_model_select + four-layer parity rerun. Then regenerate speed_report.md on the current
build and run the new confidence_error_auc.py; update README numbers if they moved.
**Blocker rule: nothing proceeds until this is fully green.**

### L2. History purge -- NEEDS VIN'S GO
The tokens (#1) and business text (#4) live in ~111 commits of history. The repo's
credibility story leans on that history ("committed before its test ran"), so we purge
surgically, not by squashing: git-filter-repo removes the affected metadata files from all
commits and blanks the redacted strings everywhere, preserving commit structure and
messages. All commit SHAs change; the handful of SHAs cited inside PROTOCOL2/docs get a
follow-up mapping commit. Force-push while still private, then re-clone verification.
This is destructive and irreversible on the remote, which is why it waits for an explicit
go. (Belt-and-braces option, Vin's call: also delete the three old round-1-3 Proof docs
from the Proof library so the exposed tokens open nothing.)

### L3. Flip public + tag
gh repo edit --visibility public, then tag v0.1.0 on main. CI runs the full gate + builds
wheels for three OSes on the tag.

### L4. GitHub Release
Create the v0.1.0 release: attach the CI wheels, release notes lead with speed + drop-in +
confidence scores, link the accuracy record, state plainly that v2 is documented but not
shipped and that PyPI publication is next.

### L5. PyPI name registration -- NEEDS VIN (credentials)
Register `fastaddress` on PyPI (or enable trusted publishing from the repo) promptly after
going public -- the README recruits usaddress users, and an unclaimed name is a squat
target. Claude cannot handle the credentials; this is a 10-minute human step. Until done,
the README's "not on PyPI yet -- this repo is the only official source" line is the guard.

### L6. Announce (separate, optional)
Launch post / HN / r/Python etc. -- draft on request. Not part of this plan's gate.

## Then: the gold-2b campaign (separate plan)
Funded by Vin's decision. Goal: a candidate that beats v43's dev-tier numbers AND clears
the gold-2b strict-cohort gates (2,912 records, 32 states, 2 attempts ever). Directions
already identified: real-text corpus expansion into gold-2b-disjoint sources, the
unalignable-45% classes (dropped suffixes, misspellings), recipient/landmark coverage, and
the 14 unadjudicated gold-1 divergences. Plan to be written when the launch settles.

## Scope boundaries
- No accuracy claims beyond the documented error classes anywhere in launch materials.
- v2 feature stays default-off; the v2 binary ships in-repo as a documented candidate only.
- Nothing in this plan touches the eval protocols or spends any evaluation surface.
